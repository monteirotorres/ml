O que é aprendizagem de máquina?

Programar com dados, não com regras

Parte 1 · O que é ML

Uma inversão de lógica

Na programação clássica escrevemos as regras; em ML, o modelo as descobre a partir de dados e respostas.

Parte 1 · O que é ML

Definição operacional (Mitchell, 1997)

  • Um programa aprende com a experiência $E$, em uma tarefa $T$, medido por $P$, se seu desempenho em $T$ melhora com $E$.
Exemplo — diagnóstico por imagem T: classificar célula (tumoral/saudável)  ·  E: imagens já rotuladas  ·  P: proporção de acertos em imagens novas.
  • Se não consegue nomear $T$, $E$ e $P$, o problema ainda não está formulado.
Parte 1 · O que é ML

Aprender = ajustar uma função

  • Buscamos uma função que mapeia características em predições:
$$\hat{y} = f(\mathbf{x}; \boldsymbol\theta)$$
  • $\mathbf{x}$ = vetor de características  ·  $\hat{y}$ = predição  ·  $\boldsymbol\theta$ = parâmetros ajustados
  • Aprender é achar $\boldsymbol\theta$ que aproxima $\hat{y}$ de $y$ — e generaliza para dados novos.
Memorizar os dados de treino não é aprender. O que importa é o desempenho em dados nunca vistos.

Generalização

O conceito mais importante do curso

Parte 3 · Generalização

Underfitting × overfitting

Mesmos pontos, três graus: simples demais (esquerda), equilibrado (centro), complexo demais (direita).

Parte 3 · Generalização

O compromisso viés–variância

  • Viés alto → modelo simplista → underfitting
  • Variância alta → modelo instável → overfitting
  • $\mathbb{E}[(y-\hat f)^2] = \text{Viés}^2 + \text{Var} + \sigma^2$
  • Reduzir um tende a aumentar o outro
Parte 3 · Validação

Validação cruzada k-fold

Cada exemplo é usado uma vez para teste e $k-1$ vezes para treino; a estimativa final é a média das rodadas.

Parte 3 · Validação

A regra inegociável

  • Dados de teste não podem influenciar nenhuma decisão do modelo
  • Pré-processamento (escala, imputação) é ajustado só no treino de cada fold
Vazamento de dados (data leakage) é o pecado capital: infla o desempenho silenciosamente. Use Pipeline para evitá-lo.
Parte 4

Métricas de avaliação

"O modelo está bom?" depende da métrica

Parte 4 · Métricas · Regressão

Resumindo os resíduos

$$\text{MAE} = \tfrac{1}{n}\sum_i |y_i-\hat{y}_i| \qquad \text{RMSE} = \sqrt{\tfrac{1}{n}\sum_i (y_i-\hat{y}_i)^2}$$
  • MAE — erro típico, robusto a outliers
  • RMSE — pune erros grandes desproporcionalmente
  • $R^2$ — fração da variância explicada; $R^2<0$ é pior que chutar a média
Parte 4 · Métricas · Regressão

MAE ou RMSE? Pergunte ao outlier

Um único erro grande dispara o RMSE, mas mal move o MAE — a escolha muda a conclusão.

Parte 4 · Métricas · Classificação

A matriz de confusão

  • VP / VN — acertos
  • FN — doente dado como saudável (o mais perigoso)
  • FP — alarme falso
  • Quase toda métrica é uma razão entre essas quatro contagens.
Parte 4 · Métricas · Classificação

Precisão × recall

$$\text{Precisão} = \frac{VP}{VP+FP} \qquad \text{Recall} = \frac{VP}{VP+FN}$$
  • Triagem de câncer → priorize recall (não perder doentes)
  • Filtro de spam → priorize precisão (não descartar e-mail bom)
  • $F_1$ = média harmônica dos dois — só é alta quando ambos são altos
Acurácia engana em classes desbalanceadas: prever "sempre saudável" numa doença rara acerta 99% — e é inútil.
Parte 4 · Métricas · Classificação

Curva ROC e AUC

  • Varia o limiar e traça recall × falsos positivos
  • AUC resume o poder discriminativo
  • 1,0 = perfeito · 0,5 = acaso
  • Independente do limiar e do desbalanceamento

Pré-processamento

Garbage in, garbage out

Parte 5 · Pré-processamento

Escala importa (para métodos de distância)

Sem padronizar, a variável de maior amplitude domina a distância. O z-score coloca todas na mesma escala.

Parte 5 · Pré-processamento

O padrão à prova de vazamento

  • Imputar faltantes, escalar e codificar categorias — tudo dentro de um Pipeline
  • ColumnTransformer aplica transformações diferentes a colunas numéricas e categóricas
scikit-learn Pipeline([("pre", ColumnTransformer(...)), ("clf", LogisticRegression())])
Cada passo é reajustado apenas no treino de cada fold — sem vazamento.
Recapitulando

As ideias que ficam

  • ML aprende padrões a partir de dados — o alvo é generalizar
  • O tipo do problema vem da pergunta, não dos dados
  • Overfitting é o inimigo nº 1; validação cruzada é a defesa
  • Escolha a métrica conforme o custo de cada erro
  • Pré-processe dentro de um pipeline para não vazar dados
